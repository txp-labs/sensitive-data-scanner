## What 0.2.0 is

The DynamoDB source, and findings schema 1.1. It is **tested, and not yet
run against real AWS**.

### Proven by tests (CI on every pull request)

- **The DynamoDB source, against botocore's Stubber:** Query of a partition
  with a sort-key prefix, Scan, projection, attribute paths with `[]` and
  `[name=value]` conditions, paging by `LastEvaluatedKey`, the page cap and
  resume, the run budget, backoff on throttling, errors named, and findings
  dropped when an item is gone or clean.
- **The proof pair, on fixtures in the shape of Stugum's call-test runs (made-up
  values):** the positive control's keypad entries are found (DOB and SSN
  high, card low, each through the prompt paired with it by `stepIndex`); the
  negative control, whose entries read `[REDACTED:ssn · asked for SSN]`, has
  zero findings. An expected-prompt regular expression in the test script is
  shown never to class an entry.
- **No value leaves** the DynamoDB source: findings, events, logs and reprs
  are searched for every fixture value, including items keyed by a card
  number and an SSN (masked, and hashed with a salt).
- **Findings schema 1.1** documents are validated against the schema.

### Not yet proven

- **No run against real AWS yet**, DynamoDB included: no real table, IAM or
  KMS permission has been used. Stugum's dev account is the first planned
  tenant.
- Everything listed as not yet proven for 0.1.0 still is: throughput and cold
  start, the event-driven phase 2, and signing.
