## What 0.1.0 is

The first release of the scanner. It is **tested, and not yet run against
real AWS**.

### Proven by tests (CI on every pull request)

- **The spec 0.1 contract:** `spec/classes.yaml` and `spec/normalize.yaml`,
  with JSON Schemas. The TypeScript package and the Python runner both pass
  **every vector**. Those include every Stugum live-run case and
  txp-labs/mermera-attestation-app#1067's fixtures. A parity test fails if the
  two implementations disagree on any vector: normalized text, offsets,
  matches, exclusions.
- **Detection:** Presidio Analyzer with no NLP model. It has card and SSN
  recognizers with the spec's rules, a DOB recognizer, spoken digits, and
  the conversational question-then-answer recognizer, with split turns.
- **The S3 and CloudWatch Logs sources and the batch runner, against moto:**
  incremental passes, one version per item, budgets and resume, stated
  sampling, partial reads, pruning deleted objects, the lock, and events.
  Every source format in the vectors parses to its turns.
- **The findings contract, schema version 1.0.** Documents are validated
  against the schema in the tests.
- **No value leaves.** Every vector is scanned end to end, and no value
  appears in findings, events, logs, exception messages or reprs. The source
  is audited so that every log call and every raised exception is safe.
- **Packaging:** the container image builds, and detection runs inside it
  with no network. The Lambda zip fits the 250 MB unzipped limit.

### Not yet proven

- **No run against real AWS yet.** No run has used real S3 or CloudWatch Logs,
  Connect or Lex data, or IAM or KMS permissions. Stugum's dev account is the
  first planned tenant.
- **Throughput and Lambda cold start** in a real account (Presidio's import
  takes about 6 s locally).
- **The event-driven phase 2** (S3 events, log subscription filters) is
  design only (docs/ARCHITECTURE.md). Pushing findings to an EventBridge bus
  works in batch mode, but it has only been tested with a stub.
- **Releases are not signed yet.** Signing (AWS Signer or cosign) and
  Mermera-side hosting are still to be decided (docs/RELEASING.md).
