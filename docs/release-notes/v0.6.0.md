## What 0.6.0 is

The release you can try without Mermera or any other tool. Every AWS run now
writes a **report a person can read**, `report.html`, and a **spreadsheet**,
`findings.csv`, next to its findings document. A **Launch Stack link per
region** deploys the scanner in a few clicks, with defaults sized for a first
look. [docs/QUICKSTART.md](../QUICKSTART.md) takes you from nothing to an
open report in about 10 minutes, and back to nothing.

**Before 1.0 a change of default bumps the minor version, and this release
changes defaults.** Read "Changed defaults" before you upgrade a stack.

### What you get

- **`findings/report.html`.** One self-contained page in the results bucket.
  It has inline styles and no script, and it makes no request of any kind:
  its Content-Security-Policy forbids them. It reads offline, prints, and
  follows your light or dark setting. It shows:
  - what was scanned and what was not, with the reason, and for each gap the
    setting that would read it;
  - findings by data type, by store and by location, each with a link into
    your own console;
  - each bucket's objects by storage class, and what reading the cold ones
    would cost;
  - the scanner version, the run, and where the code's signature is.
  - **It never shows a value**: it is made from the findings document alone,
    and every name is masked again on the way out.
- **`findings/findings.csv`.** One row per finding location: data type,
  severity, count, confidence, store, location, region, first and last seen.
  A name that would start a spreadsheet formula is quoted, so a spreadsheet
  shows it as text.
- **A Launch Stack link per region.** us-east-1, us-east-2, us-west-2,
  ca-central-1, eu-west-1, eu-central-1 and ap-southeast-2, in the README
  and QUICKSTART.md. Each opens CloudFormation's quick-create page with this
  release's template from that region's bucket
  (`releases/0.6.0/scanner.yaml`). The quick-create defaults are: one
  account and region, discovery on, opt-in reads off, and a 256 MiB first
  run.
- **A sample report** in [docs/sample-report/](../sample-report/report.html).
  It comes from a simulated run over the made-up benchmark corpus.
- **The other runners can write the report too.** The core makes both files
  (`sensitive_data_core.report.report_files`). In this release only the AWS
  scanner writes them.

### Changed defaults

- **Code signing is on by default for zip deployments.**
  `CodeSigningProfileVersionArn` now defaults to `release`. The template
  takes txp-labs' signing profile version for the stack's own region from
  its own table, and Lambda refuses any zip that profile did not sign. So one
  StackSet value now works in every region. An ARN still names a profile
  version; empty turns code signing off. In a region txp-labs does not
  publish to, `release` attaches nothing. With `ImageUri` none of this
  applies: the image is verified with cosign.
- **The templates default to txp-labs' hosted release.** In `scanner.yaml`
  and `estate-stackset.yaml`, `CodeS3BucketPrefix` defaults to
  `txp-labs-sensitive-data-scanner` (the release bucket in the stack's
  region), and `CodeS3Key` defaults to this release's zip. Before, both were
  empty, so the zip had to be named. A stack that already passes its own
  values keeps them.
- **`ReportCta` is a new parameter, default empty.** The report ends with a
  one-line invitation to Mermera's early access. That line is left out
  automatically when the scanner is connected to Mermera, meaning
  `FindingsHttpsUrl` is set or the run's settings pull succeeded. `true` or
  `false` overrides that either way.
- **`MaxBytesPerRun` is a new parameter, default empty.** Empty keeps the
  scanner's 2 GiB a run. The Launch Stack links set it to 268435456 (256 MiB)
  so a first run ends in minutes. A quick-start stack keeps that budget on
  its daily schedule until you update the stack with the parameter empty.
  QUICKSTART.md says how.
- New stack output **`Report`**: the S3 location of the latest report.

All scan costs land on your own AWS bill. Per [docs/COST.md](../COST.md), one
run is capped at about $0.044 of Lambda compute at us-east-1 list prices.

### What this release proves, and what it does not

**Proven before tagging, in CI:**
- The no-leak suite reads both new files in every form a reader could see:
  as written, with HTML entities decoded, URL-decoded, as page text, and with
  digit groups joined. Values are planted in the data and in bucket, key,
  log group and stream names. The committed sample is checked against every
  value planted in the benchmark corpus.
- Snapshot tests cover both files.
- An accessibility check covers the page: headings, captioned tables with
  scoped headers, link text, and WCAG AA contrast in both color schemes.
- The templates are linted, and their signing table is held equal to the
  release workflow's and to docs/RELEASING.md.

**Proven only by this release's own run:**
- **The Launch Stack links work only once this release has published
  `scanner.yaml` in each region.** The `aws-publish` job uploads it
  write-once to `releases/0.6.0/scanner.yaml` in all seven buckets and reads
  it back anonymously. Until that job has finished, the links fail. Nothing
  earlier published a template there: 0.5.0's links never existed.
- Signing, the upload rule, cosign and npm provenance, as for 0.5.0.

**Not yet proven:**
- A quick-create deploy and a report written in a real account. Every
  report test runs against simulated AWS. Walk QUICKSTART.md once in a real
  account after this release's run, before announcing it.
- Code signing enforced by default has not been deployed in a real account.

Everything else stands as in 0.5.0: whole-account scans have run for real in
two AWS development accounts and one Microsoft 365 tenant. Azure, Google
Cloud and the other SaaS sources are tested against simulated services only.
