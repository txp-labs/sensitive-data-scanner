## What 0.3.0 is

The scanner now covers a **whole AWS estate**: it finds every data store in
every account and region it is deployed to and reads each one, with no list
for you to write. It also brings spec 0.4 and findings schema 1.3, and the
fixes from the first run in a real account. The S3, CloudWatch Logs and
DynamoDB paths have run in a real account; **every store added in this
release is tested, and not yet run against real AWS**.

### What you get

- **Discovery instead of configuration.** Each run lists the stores in its
  account and region and reads them: S3, CloudWatch Logs, DynamoDB, Glue
  tables, RDS and Aurora, Redshift, OpenSearch, EBS, Kinesis and Firehose,
  SQS dead-letter queues, Parameter Store, Secrets Manager, Timestream and
  Keyspaces. Allow and deny rules by name or tag stay available as
  overrides.
- **Data lakes and databases without database passwords.** Parquet, ORC and
  Avro files are read by column; Glue tables are read at their S3 location
  with Lake Formation respected; RDS and Aurora are read from a snapshot
  export, so the database takes no load. Findings name the database, table
  and column.
- **One rollout for an organization.** `estate-stackset.yaml` deploys the
  scanner to every account of the organizational units and every region you
  name, including accounts that join later, and sends findings to one
  central EventBridge bus.
- **Cost controls.** Sampling per store, a budget per run by kind and by
  wall time, and incremental runs that resume where the last one stopped.
- **A coverage report.** Every run lists every store it found, read or not,
  and why: denied by a rule, too large, opt-in and not enabled, a key the
  scanner may not use, and so on. Anything the scanner cannot read is a
  named gap, never a silent one.
- **Read-only everywhere.** The templates grant reads only, with explicit
  denies on writes. Reads that are more intrusive (SQL on a live database,
  EBS block reads, dead-letter queues, secrets) are off until you turn them
  on.
- **Findings never carry a value.** Store, table and column names that hold
  something that looks like a card or SSN are masked too.

### Proven by tests (CI on every pull request)

- Every new store against stubbed AWS APIs: discovery, sampling, paging,
  budgets and resume, and each reason a store is reported rather than read.
- The no-leak suite covers every new store, with made-up values planted in
  cells, documents, messages, parameters, and in bucket, table, column and
  index names.
- The IAM in `scanner.yaml` allows every call the code makes, allows no
  write it does not need, and documents every action it allows.
- The spec 0.4 phrases pass in the Python engine, the Presidio path and the
  TypeScript package alike.
- The Lambda zip fits the 250 MB unzipped limit; the container image reads
  Parquet and ORC.

### Proven in a real account

- The v0.2.0 run in Stugum's dev account (S3, CloudWatch Logs and DynamoDB)
  passed its proof, and the four problems it found are fixed here: the
  first-run state file without `s3:ListBucket`, configuration beyond
  Lambda's 4 KB of environment variables, console links on findings with a
  masked key, and the checksum file's asset names.

### Not yet proven

- **No store added in this release has run against real AWS**, and neither
  has the StackSet rollout.
- **Throughput and cold start** at estate scale.
- **The event-driven phase 2** is still design only.
- **EFS and FSx** are reported as needing a file-system task, which is
  designed and not built.
- **Releases are not signed yet** (docs/RELEASING.md).
